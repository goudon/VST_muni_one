# Muni フェイス表示 (`MuniFace`)

[example/muni.png](example/muni.png) のキャラクター (muni) を、パーツ画像をレイヤー合成して
プラグイン GUI 上に再現するコンポーネント。実行時に使うパーツ画像は `src/img/`、
そのソース (再リサイズ用に保管している高解像度版) は `resources/source_img/` にある。

将来的にユーザがパーツ (目・耳・眉・鼻) を直接マウス操作してパラメータを編集できる
インタラクティブ UI に拡張するための基盤として、各パーツを独立した画像として描画する。

## ソース画像 (バイナリ同梱)

`src/img/` 以下の PNG を `juce_add_binary_data` で実行ファイルに埋め込み、
`BinaryData::*` 経由で読み込む (CLAUDE.md: 動的ファイルロード禁止)。

| 識別子 | 用途 | サイズ (px) | 補足 |
|-------|------|-------------|------|
| `muni_fbase_png`     | 顔ベース (頭部 + ヘッドフォン)        | 208 × 196 | 全パーツの基準サイズ |
| `muni_ear_png`       | 耳 (片側) — 茶色のしずく形           |  65 × 91  | 左右で水平反転 |
| `muni_eye_png`       | 目 (黒い縦長楕円)                    |  21 × 41  | 左右で同一 |
| `muni_eye_brow_png`  | 眉 (傾きを持つ細長いシェイプ)        |  11 × 7   | 左右で水平反転 |
| `muni_nose_png`      | 鼻 (中央配置)                        |  25 × 16  | 単一 |

## 描画方針 — リサイズなしのネイティブピクセル描画

`MuniFace` は受け取ったコンポーネント領域の中央に、**顔ベース画像をネイティブ
ピクセルサイズのまま** 配置する。各パーツも自身の画像サイズで一切スケールせずに
描画する。したがってウィンドウの大小によらず muni の見た目は常に同じ実サイズで
表示される (画面に対する相対サイズだけ変化する)。

スケールを排しているので `juce::Graphics::drawImage` の補間アーティファクトが
出ず、ピクセルアートの輪郭がそのまま保たれる。代わりに、表示領域がパーツ画像より
小さい場合は端が切れる点に注意 (現状のエディタサイズ 360×320 では耳が最大回転
±0.5 rad + パルス +8% でも収まるよう左右に約 60 px ずつの余白を確保している。
詳細は [layout.md](layout.md))。

## レイヤー順 (奥→手前)

`muni.png` を再現するための描画順:

1. 耳 (左, 右) — 顔ベースの裏に隠れて下部から少し覗く位置
2. 顔ベース (`muni_fbase_png`)
3. 目 (左, 右)
4. 眉 (左, 右)
5. 鼻 (中央)

## 配置 (顔ベース画像内のピクセル座標)

各パーツは「顔ベース画像内における **中心ピクセル座標**」で位置決めする。
サイズはパーツ画像自身の幅・高さをそのまま使う。

**命名規約**: 耳・眉の `kLeft*` / `kRight*` は **キャラクター視点** (向かって左 =
画面右、向かって右 = 画面左)。目は左右対称な同一画像を使うため、ラベルが
画面側基準になっており命名規約は緩い (実害なし)。

| パーツ | 中心 (cx, cy) px | 画面上の位置 | 使用画像 (反転) |
|-------|------------------|---------------|-------------------|
| `kRightEar`  (キャラ右耳) | (23, 151)  | 画面左下 | `earFlipped` (水平反転) |
| `kLeftEar`   (キャラ左耳) | (185, 151) | 画面右下 | `ear` (元画像のまま) |
| `kLeftEye`                | (74, 105)  | 画面左   | `eye` |
| `kRightEye`               | (134, 105) | 画面右   | `eye` |
| `kRightBrow` (キャラ右眉) | (73, 74)   | 画面左   | `eyebrowFlipped` (水平反転) |
| `kLeftBrow`  (キャラ左眉) | (135, 74)  | 画面右   | `eyebrow` (元画像のまま) |
| `kNose`                   | (104, 130) | 中央     | `nose` |

数値は顔ベース 208×196 ピクセルの座標系における中心位置。実機で見て微調整する。
ソースの `muni_ear.png` / `muni_eye_brow.png` は **キャラクター左側用 (画面右側)** の
向きで描かれているため、元画像をそのまま使う側が `kLeft*`、反転コピーを使う側が
`kRight*`。

## レンダリング上の注意

- 描画は `juce::Component::paint()` 内のみで行う (RT スレッドではない)。
- ピクセルパーフェクト配置のため `g.drawImageAt(int, int)` を使用 (整数座標)。
- **反転は事前計算**: コンストラクタで `flipHorizontally()` (ピクセル単位の水平反転)
  により `earFlipped` / `eyebrowFlipped` を生成し、`paint()` ではこれらを直接
  `drawImageAt` で描く。`drawImageTransformed` の負スケールはレンダラ実装によって
  反映されないことがあるため、**描画時に AffineTransform で反転しない方針**。
- `flipHorizontally()` は `juce::Image::BitmapData` を使い 1 ピクセルずつ
  `memcpy` で反転コピー。確実に動作し、開始時の 1 回のみで完了するため
  paint() コストは増えない。
- 画像のロードは `juce::ImageCache::getFromMemory()` を使用し、複数回構築されても
  実体は共有される。

## インタラクション (ドラッグ操作)

`MuniFace` は APVTS への参照を保持し、各パーツをマウスでドラッグするとそれに対応する
パラメータを更新する。詳しい対応表は `docs/parameters.md` の「キャラクター GUI ↔
パラメータ マッピング」を参照。

### 自由度

| パーツ | 動作 |
|-------|------|
| 鼻 | 縦ドラッグのみ (Y) |
| 目 | 縦 (Y) + 横 (間隔) — 左右ミラー (どちらを掴んでも同パラメータ更新) |
| 眉 | 縦 (Y) + 横 (間隔) — 左右ミラー |
| 耳 | 横ドラッグ → 回転 (左右独立) |

### 実装ポイント

- ヒットテストは `paint()` と同じ `LayoutCache` を使い、各パーツの軸並行 BBox に対する
  含有判定で行う。耳の回転後の正確な当たり判定は省略 (小角度なら誤差小)。
- ドラッグ中: `mouseDown` で `beginChangeGesture()` + 起点正規化値の保存 → `mouseDrag` で
  デルタを正規化値に変換して `setValueNotifyingHost()` → `mouseUp` で `endChangeGesture()`。
  これにより DAW のオートメーション記録が 1 つの操作として丸まる。
- 外部 (DAW オートメーション・スライダー) からの値変更にも追従するため、
  `juce::AudioProcessorValueTreeState::Listener` と `juce::AsyncUpdater` を実装し、
  `parameterChanged` で `triggerAsyncUpdate()` を呼ぶ (オーディオスレッドからの
  ヒープ確保を回避)。`handleAsyncUpdate` で `repaint()` を呼ぶ。同一フレーム内に
  複数 fired されても `handleAsyncUpdate` は 1 度に統合される (自動デバウンス)。
- パラメータ参照は `apvts.getParameter(id)` をコンストラクタで 1 度だけ引いて
  `RangedAudioParameter*` をキャッシュ。`paint()` / `mouseDrag` は ID 文字列検索を
  経ずに直接アクセスする。
- パーツの現在位置は毎フレーム正規化値から再計算 (`computeLayout()`)。
  正規化値 0.5 のときベース座標 (顔ベース内ピクセル) と一致するよう
  `(norm - 0.5) * 2 * range` でセンター付き対称オフセットへ変換。
- 耳の回転は `juce::Graphics::ScopedSaveState` + `addTransform` + `drawImageAt` で実装
  (負スケールを使わないので `drawImageTransformed` の信頼性問題を回避)。
  ピボット = 耳画像の上端中央寄り (`center.y - h * 0.4`)。

### ノートオン パルスアニメーション

- MIDI ノートオン受信時に muni 全体が **+8% 拡大 → 約 165 ms で減衰** するパルス。
- オーディオスレッド側 (`MuniAudioProcessor::processBlock`) で note-on を検出したら
  `noteTriggerCount` を `fetch_add` (relaxed)。GUI 側 `MuniFace` の Timer (30 Hz)
  がカウンタを polling し、変化を検出したら `pulseLevel` を 1.0 にスナップ。
- 毎ティック `pulseLevel *= 0.70` で減衰、`< 0.005` でゼロ化。
- `paint()` 冒頭で `juce::Graphics::ScopedSaveState` + `addTransform(scale(s, s, pivot))`
  を顔ベース中央に適用。耳の回転や目・眉のドラッグ位置も含めて顔全体が単一トランスフォーム
  内で描画されるため、パーツが分離せず一体で拡大する。
- 連続ノート時はタイミングごとにパルスがリスタートする (前のパルスは即時上書き)。
- スケール係数は [src/gui/MuniFace.cpp](src/gui/MuniFace.cpp) の `kPulsePeakScaleAdd` /
  `kPulseDecayPerTick` / `kPulseTimerHz` で調整可能。

### サイン規約 (適当な暫定)

- 鼻: ドラッグ下 → `gain` 減 (レンジ -15 〜 +15 dB)
- 目: ドラッグ下 → `attack` 長く / **内側 (中心寄り)** → `pitch` 上がる (外側 → 下がる)
- 眉: ドラッグ上 → `release` 長く / **内側 (中心寄り)** → `speed` 速く (外側 → 遅く、縦位置は目とオーバーラップしないようキャップ)
- 耳: ドラッグ右 → 時計回り回転

数値表示は現段階では行わない (パーツの動きが直接フィードバック)。

  はスケーリングを行わない)。
